# Alpha Trade - 策略开发与实盘使用流程

## 目标

这个项目的目标很简单：找到一个长期大概率能赚钱、风险可控、可以用于实盘的交易策略。

整个系统围绕一条主线工作：

```text
拉取数据 -> 写策略 -> 回测 -> 评估稳定性 -> 优化参数 -> 样本外验证 -> 接入实盘信号
```

不要只追求某一次回测收益高。一个策略要能实盘使用，必须证明它不是因为数据缺失、参数过拟合、手续费低估或某一个特殊行情窗口才赚钱。

## 系统做什么

| 模块 | 作用 |
| --- | --- |
| 数据 | 从 Binance 拉 K线，存到 PostgreSQL，并检查缺失、重复、异常价格 |
| 策略 | 编写趋势、震荡、组合策略 |
| 回测 | 用历史数据模拟交易，输出收益、回撤、交易明细 |
| 评估 | 看策略在不同时间段和不同交易成本下是否稳定 |
| 优化 | 找参数候选，但不能直接把最优参数当实盘参数 |
| 实盘信号 | 最终把通过验证的策略接入 `main.py signal` |

## 当前策略

现在系统里有这些策略：

| 策略 | 说明 | 当前用途 |
| --- | --- | --- |
| `ma_cross` | 双均线趋势策略 | 旧基线 |
| `rsi_revert` | RSI 均值回归策略 | 旧基线 |
| `trend_breakout` | Donchian 突破 + 趋势过滤 | 趋势策略原型 |
| `bollinger_revert` | Bollinger + RSI + 低 ADX | 震荡策略原型 |
| `regime_switch` | 根据市场状态切换趋势/震荡逻辑 | 当前主候选 |

当前最值得继续验证的是 `regime_switch`。

注意：`main.py signal` 现在还没有切到 `regime_switch`，实盘信号仍偏旧的 `MaCross` 逻辑。`regime_switch` 还需要完成样本外验证、多资产验证和参数稳定性验证后，才能接入实盘。

## 如何生产一个好策略

### 1. 先说清楚策略赚什么钱

每个策略都要先回答：

- 它适合趋势行情，还是震荡行情？
- 它靠什么入场？
- 它什么时候退出？
- 它在哪里止损？
- 它为什么在手续费和滑点后仍然有利润？

如果这些说不清，就不要先调参数。

### 2. 先确认数据完整

回测前必须检查数据质量：

- K线有没有缺失。
- 有没有重复 K线。
- 时间是不是 UTC。
- OHLC 有没有异常。
- 成交量是否正常。

2024 年 `ETH/USDT 1h` 数据已经补齐：

```text
区间: 2024-01-01 ~ 2025-01-01
K线: 8785 根
缺失: 0
重复: 0
```

### 3. 策略必须带风控

策略不能只给买卖信号，还要控制亏损。

现在 `BaseStrategy` 已经提供通用风控：

- 按止损距离计算仓位。
- 单笔最大风险 `risk_per_trade`。
- 最大仓位比例 `max_position_pct`。
- 连续亏损后的冷却期。
- 时间止损。
- ATR 跟踪止损。
- 最大回撤后停止交易。

新策略应该复用这些风控，不要每个策略重复写一套。

### 4. 先评估，再优化

正确顺序是：

```text
默认参数回测 -> 分段评估 -> 成本压力测试 -> 参数优化 -> walk-forward -> 多资产/多周期验证 -> 实盘信号
```

不要反过来一上来就跑大网格优化。那样很容易找到一个只适合历史数据的参数。

## 如何评估策略

### 单次回测

用来快速看一个策略在某段历史上的表现。

```bash
.venv/bin/python main.py backtest -s regime_switch -t 1h --start 2024-01-01 --end 2025-01-01
```

看这些指标：

- Return：策略收益。
- Buy & Hold：买入持有收益。
- Cash Benchmark：空仓收益，固定为 0%。
- Sharpe：风险调整收益。
- Max Drawdown：最大回撤。
- Trades：交易次数。
- Win Rate：胜率。
- Profit Factor：总盈利 / 总亏损。
- Commissions：手续费。
- 数据质量：缺失、重复、异常 K线。

报告输出到：

```text
artifacts/backtests/
```

### 稳定性评估

用来判断策略是不是只靠某一个时间段赚钱，以及是否怕手续费和滑点。

```bash
.venv/bin/python main.py evaluate -s regime_switch -t 1h --start 2024-01-01 --end 2025-01-01
```

它会输出：

- 全区间结果。
- 年度结果。
- 季度结果。
- 成本压力测试。

成本压力测试包含：

```text
commission: 0.05%, 0.10%, 0.20%
slippage:   0.05%, 0.10%, 0.20%
```

报告输出到：

```text
artifacts/evaluations/
```

### 参数优化

用来找可能更好的参数区间。

```bash
.venv/bin/python main.py optimize -s regime_switch -t 1h --start 2024-01-01 --end 2025-01-01
```

优化结果只能作为候选，不能直接上线。

### Walk-Forward

用来验证参数是不是样本外也有效。

```bash
.venv/bin/python main.py walkforward -s regime_switch -t 1h --start 2023-01-01 --end 2026-01-01 --train-months 12 --test-months 6
```

如果策略在训练区间赚钱，但测试区间持续亏钱，说明大概率过拟合。

## 什么策略可以进入实盘

策略要进入实盘，至少要满足：

- 数据质量 OK。
- 交易次数足够，至少 30 笔；低频策略要单独说明。
- Profit Factor > 1。
- Sharpe 为正。
- 最大回撤可接受。
- 不只靠一个季度赚钱。
- 高成本测试后不能明显失效。
- Walk-forward 样本外不能持续亏损。
- 多资产、多周期不能全部失效。
- 实盘信号和回测信号在同一根历史 K线上一致。

不满足这些条件，只能继续研究，不能接入实盘。

## 当前 `regime_switch` 结果

评估区间：

```text
策略: regime_switch
交易对: ETH/USDT
周期: 1h
区间: 2024-01-01 ~ 2025-01-01
```

全区间：

| 指标 | 结果 |
| --- | ---: |
| Return | 6.05% |
| Buy & Hold | 45.86% |
| Sharpe | 0.76 |
| Max Drawdown | -4.07% |
| Trades | 45 |
| Profit Factor | 1.34 |

季度：

| 季度 | Return |
| --- | ---: |
| Q1 | -0.54% |
| Q2 | 1.81% |
| Q3 | 1.14% |
| Q4 | 1.68% |

成本压力：

- 默认成本下表现可以。
- 最高成本 `commission=0.20%`、`slippage=0.20%` 时，收益降到 0.45%，Profit Factor 降到 0.91。

结论：

`regime_switch` 有初步盈利能力，但边际偏薄，还不能直接实盘。下一步应该做 walk-forward、参数稳定性、多资产和多周期验证。

## 下一步

优先做这几件事：

1. 增强 walk-forward，输出样本外收益、参数漂移和淘汰原因。
2. 做参数稳定性表，确认策略不是只在一个参数点赚钱。
3. 拉取 BTC/USDT、SOL/USDT 等数据，做多资产验证。
4. 测试 4h、1d 周期。
5. 如果策略通过验证，再把 `regime_switch` 接入 `engine.signal`。
