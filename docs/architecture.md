# Alpha Trade - 以太坊 USDT 量化交易系统架构

## 项目概述

Alpha Trade 是一个以太坊 USDT 量化交易系统，通过 **数据采集 → 策略开发 → 回测验证 → 策略迭代** 的闭环流程，持续优化交易策略的可行性与收益表现。

## 系统架构总览

```
┌─────────────────────────────────────────────────────────┐
│                    Alpha Trade System                   │
├──────────┬──────────┬──────────────┬────────────────────┤
│  数据层   │  策略层   │    回测层     │     执行层         │
│          │          │              │                    │
│ · 行情采集 │ · 策略编写 │ · 历史回测    │ · 信号生成         │
│ · 数据清洗 │ · 因子计算 │ · 绩效评估    │ · 订单管理         │
│ · 数据存储 │ · 信号生成 │ · 风险分析    │ · 风控执行         │
└──────────┴──────────┴──────────────┴────────────────────┘
```

## 核心流程

```
数据拉取 ──→ 策略制定 ──→ 回测验证 ──→ 分析结果
   ↑                                    │
   │         策略迭代优化                  │
   └────────────────────────────────────┘
```

## 数据层

### 数据源

| 数据类型 | 来源 | 说明 |
|---------|------|------|
| K线数据 | Binance / OKX / Coinbase API | ETH/USDT 交易对的 OHLCV 数据 |
| 链上数据 | Etherscan / Infura / Alchemy | 链上交易量、Gas 费、大额转账 |
| 订单簿数据 | 交易所 WebSocket | 实时买卖盘深度 |
| 资金费率 | 合约交易所 API | 永续合约资金费率 |
| 社交情绪 | Twitter API / LunarCrush | 市场情绪指标 |

### 存储方案

- **历史数据**：PostgreSQL
- **实时数据**：Redis 缓存
- **数据粒度**：1m / 5m / 15m / 1h / 4h / 1d

## 策略层

### 策略分类

| 策略类型 | 典型方法 | 适用场景 |
|---------|---------|---------|
| 趋势跟踪 | MA交叉、MACD、布林带突破 | 单边行情 |
| 均值回归 | RSI超买超卖、布林带回归 | 震荡行情 |
| 动量策略 | 价格动量、成交量突破 | 波动加剧时 |
| 统计套利 | 跨交易所价差、期现套利 | 低风险稳定收益 |
| 机器学习 | LSTM、XGBoost、强化学习 | 复杂模式识别 |

### 因子体系

- **技术因子**：MA、EMA、RSI、MACD、ATR、布林带
- **链上因子**：活跃地址数、Gas 费变化率、大额转账频率
- **情绪因子**：恐惧贪婪指数、社交媒体提及量
- **信号合成**：多因子加权打分 → 归一化 → 阈值过滤 → 交易信号

---

## 回测层

### 回测流程

```
加载历史数据 → 逐 Bar 回放 → 策略生成信号 → 风控检查 → 模拟撮合 → 绩效评估
```

### 核心绩效指标

| 指标 | 说明 | 参考基准 |
|------|------|---------|
| 年化收益率 | 策略年化回报 | > 买入持有收益 |
| 夏普比率 | 风险调整后收益 | > 1.5 |
| 最大回撤 | 最大亏损幅度 | < 20% |
| 胜率 | 盈利交易占比 | > 50% |
| 盈亏比 | 总盈利 / 总亏损 | > 1.5 |

---

## 策略迭代

```
分析回测结果 → 识别问题 → 调整策略（调参/加因子/改逻辑/加风控） → 重新回测 → 达标则进入模拟盘
```

### 防止过拟合

- Walk-Forward 滚动窗口验证
- 多交易对交叉验证
- 参数稳健性检验
- 交易成本敏感性测试
