# 获得一个好策略的下一步计划

日期：2026-05-18

## 当前判断

现有系统已经能完成：

- 数据拉取和数据质量检查。
- 单策略回测。
- 年度、季度和成本压力评估。
- 参数搜索和尾部样本外复测。
- 固定参数 walk-forward。
- 通用风控：仓位、止损、冷却、时间止损、ATR 跟踪止损、最大回撤熔断。

但当前还没有一个可以接入实盘的策略。

关键结论：

- `ma_cross` 前三个高年化候选已经验证失败：全区间亏损，walk-forward 只有 `1/3` 测试窗口盈利。
- `regime_switch` 有低回撤和初步正收益，但收益边际薄，高成本下失效，不适合作为当前最终策略。
- 继续扩大 `ma_cross` / `regime_switch` 现有网格，大概率只会放大过拟合。

下一阶段目标不是继续找单次回测最高收益，而是构造一个能通过样本外、多资产、多周期和成本压力测试的策略。

## 好策略的定义

一个候选策略只有同时满足以下条件，才进入实盘信号准备阶段：

| 检查项 | 最低标准 |
| --- | --- |
| 数据质量 | 缺失、重复、异常价格、非正成交量必须有明确处理口径 |
| 全区间收益 | 正收益，且不能明显跑输空仓基准 |
| 样本外表现 | walk-forward 测试窗口多数盈利 |
| 交易样本 | 单资产单周期至少 30 笔；低频策略必须说明原因 |
| Profit Factor | 基础成本下 `> 1.1`，高成本下不能跌破 `1.0` |
| Sharpe | 样本外为正 |
| 最大回撤 | 必须可解释，且与收益目标匹配 |
| 分段稳定性 | 不能只靠一个季度或一个窗口赚钱 |
| 多资产验证 | 至少 3 个交易对中有 2 个不失效 |
| 多周期验证 | 至少 2 个周期中有 1 个稳定，另一个不能明显反向 |
| 实盘一致性 | 同一根已闭合 K线，实盘信号与回测信号一致 |

如果这些条件不满足，该策略只能继续研究，不能接入 `main.py signal`。

## Phase 1：先固定数据和验证入口

目标：后续所有策略验证都在同一套可靠入口上完成。

任务：

- [ ] 人工确认 `2023-03-24` Binance 原始缺口处理口径。
  - 缺失：`2023-03-24 13:00:00+00:00`
  - 零成交量：`2023-03-24 12:00:00+00:00`
- [ ] 支持 CLI 指定交易对，不再只能使用配置中的单一 `ETH/USDT`。
  - `backtest --pair BTC/USDT`
  - `evaluate --pair BTC/USDT`
  - `search --pair BTC/USDT`
  - `walkforward --pair BTC/USDT`
- [ ] 批量数据拉取并验证：
  - `BTC/USDT`: `1h`, `4h`
  - `ETH/USDT`: `1h`, `4h`
  - `SOL/USDT`: `1h`, `4h`
  - `BNB/USDT`: `1h`, `4h`
- [ ] 输出统一数据质量报告，记录每个交易对和周期是否可用于验证。

验收标准：

- 每个待验证交易对/周期都有明确的数据质量状态。
- 有缺口的数据不能默默进入最终结论。
- 后续命令不需要修改配置文件就能切换交易对。

## Phase 2：开发趋势持仓 v3

目标：做一个真正以趋势右尾为收益来源的策略，而不是继续在均线交叉上调参。

策略假设：

- 加密货币的大部分收益来自少数趋势扩张阶段。
- 策略应该少做震荡、尽量持住趋势，而不是频繁均线交叉进出。
- 入场可以轻仓，盈利后才考虑加仓。

候选逻辑：

- 高周期趋势确认：
  - 4h EMA 或 1d EMA 向上。
  - 价格在高周期趋势线上方。
- 低周期入场：
  - Donchian 突破。
  - 或 EMA 回踩后重新站上。
- 波动率过滤：
  - ATR 分位数过滤极低波动。
  - ATR 分位数过滤极端急跌。
- 出场：
  - ATR 跟踪止损。
  - Donchian 下轨或 EMA 结构破坏。
  - 不使用过短时间止损强行退出盈利趋势。
- 仓位：
  - 继续使用 `BaseStrategy` 按止损距离计算仓位。

暂不做：

- 不加机器学习。
- 不加链上或情绪数据。
- 不做复杂组合优化。

验收标准：

- 在 `ETH/USDT 1h` 上先跑通，交易数不少于 30。
- 全区间、年度、季度和成本压力测试全部输出。
- 如果收益只来自一个季度，直接判定失败。

## Phase 3：开发突破加仓策略

目标：在趋势持仓 v3 有正期望后，再验证加仓是否能提高收益质量。

策略假设：

- 首次突破不确定性高，应该轻仓。
- 浮盈后市场证明方向正确，再使用剩余风险预算加仓。
- 加仓必须受总仓位和账户回撤限制。

候选逻辑：

- 首次突破：使用基础风险预算的 `50%`。
- 第一次加仓：价格相对入场价浮盈达到 `1R`。
- 第二次加仓：价格创新高且趋势过滤仍然成立。
- 总仓位不超过 `max_position_pct`。
- 总风险不超过配置风险预算。

验收标准：

- 与不加仓版本相比，样本外年化收益提高。
- 最大回撤不能同步明显扩大。
- 最差季度不能恶化到不可接受。
- 高成本压力测试后 Profit Factor 不能跌破 `1.0`。

## Phase 4：多资产和多周期验证

目标：证明策略不是只适配 `ETH/USDT 1h`。

验证矩阵：

| Pair | 1h | 4h |
| --- | --- | --- |
| BTC/USDT | 必测 | 必测 |
| ETH/USDT | 必测 | 必测 |
| SOL/USDT | 必测 | 必测 |
| BNB/USDT | 必测 | 必测 |

每个组合都要输出：

- 全区间收益。
- 年度收益。
- 季度收益。
- 成本压力测试。
- 交易次数。
- Profit Factor。
- Sharpe。
- 最大回撤。

通过标准：

- 至少 3 个交易对中有 2 个基础成本下为正。
- 至少 1 个周期稳定，另一个周期不能完全反向失效。
- 如果只在单一币种有效，判定为过拟合风险，不进入实盘。

## Phase 5：参数稳定性验证

目标：确认策略不是单点参数有效。

任务：

- [ ] 对核心参数输出邻域表格：
  - 趋势周期。
  - 突破周期。
  - ATR 周期。
  - ATR 止损倍数。
  - 波动率分位数阈值。
- [ ] 对邻近参数做样本外复测。
- [ ] 输出参数稳定性报告。

通过标准：

- 最优参数周围至少有多个邻近组合表现接近。
- 不能只有一个孤立参数盈利。
- 如果参数轻微变化就失效，策略不能进入实盘。

## Phase 6：实盘信号一致性

目标：让实盘信号和回测信号使用同一套策略、参数、风控和已闭合 K线。

任务：

- [ ] 参数文件落盘：
  - 策略名。
  - 交易对。
  - 周期。
  - 参数。
  - 训练区间。
  - 验证区间。
  - 生成时间。
- [ ] `main.py signal` 支持指定策略和参数文件。
- [ ] `signal` 只使用已闭合 K线。
- [ ] 增加一致性测试：选一根历史 K线，回测信号和 signal 输出必须一致。

验收标准：

- 不再固定使用旧 `MaCross` 逻辑。
- 实盘信号不读取未闭合 K线。
- 没有通过验证的参数文件不能用于实盘信号。

## Phase 7：上线前纸面运行

目标：在真实时间流中观察信号质量，但不下单。

任务：

- [ ] 每小时或每 4 小时记录一次信号。
- [ ] 记录当时价格、信号、止损、仓位建议。
- [ ] 对纸面信号做事后复盘。
- [ ] 连续运行至少 2 到 4 周。

通过标准：

- 信号频率和回测接近。
- 没有明显重复信号或未闭合 K线漂移。
- 纸面交易和回测预期方向一致。

## 优先执行顺序

1. 先做 CLI `--pair` 支持和批量数据质量报告。
2. 拉取并验证 BTC/ETH/SOL/BNB 的 `1h` 和 `4h` 数据。
3. 开发趋势持仓 v3，不做加仓。
4. 跑完整评估矩阵。
5. 如果趋势持仓 v3 失败，停止该方向，重新定义策略假设。
6. 如果趋势持仓 v3 通过，再开发突破加仓。
7. 做参数稳定性和多资产复测。
8. 最后才改 `main.py signal`。

## 暂停条件

遇到以下任一情况，停止继续调参：

- 全区间为正，但年度分段多数为负。
- 样本外窗口多数亏损。
- 高成本下 Profit Factor 跌破 `1.0`。
- 只在单一交易对有效。
- 参数邻域不稳定。
- 收益主要来自少数 1 到 2 笔交易。

暂停后不要扩大网格，应该回到策略假设层重新设计。

下一次开发从这里开始：

```text
4. 输出多资产数据质量报告
```

完成这四步后，再开始写趋势持仓 v3。
