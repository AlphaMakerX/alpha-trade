# Alpha Trade - 策略与回测系统优化计划 v2

日期：2026-05-14

## 目标

当前系统已经能完成数据拉取、基础策略回测、参数网格搜索和 Walk-Forward 分析，但策略表现不稳定，且部分回测统计口径会误导判断。本计划的目标不是继续盲目调参，而是先把回测可信度、绩效归因、风控和策略验证流程补齐，再做策略迭代。

优化后的系统应达到以下标准：

- 回测结果可复现，且不会被未平仓交易、缺失滑点、数据缺口或单一指标误导。
- 每个策略都能输出全区间、年度、月度、交易级别、成本敏感性和样本外表现。
- 策略选择以风险调整收益和稳定性为核心，而不是只看单次收益率。
- 实盘信号与回测使用同一套参数、同一套风控和同一套数据完整性检查。

## 为什么回测效果不好

### 1. 回测口径不够严格

`engine/backtest.py` 创建 `Backtest` 时只传了 `cash` 和 `commission`，没有传入 `finalize_trades=True`、`spread/slippage` 和统一的撮合配置。结果是：

- 未平仓交易不会计入交易统计，导致 `# Trades`、胜率、Profit Factor、SQN 等指标失真。
- `config/settings.yaml` 中配置了 `slippage: 0.0005`，但当前回测没有使用它。
- 回测收益包含持仓浮盈浮亏，但交易明细可能不包含最后一笔交易，策略评估会被高估或低估。

### 2. 优化目标过窄

当前 `_grid_search_with_progress()` 只用 `SQN` 选最优参数。这个目标有几个问题：

- 交易次数太少时，`SQN` 本身不稳定。
- 没有约束最大回撤、交易次数、手续费消耗、年化波动、样本外表现。
- 最优参数没有持久化，实盘 `signal` 仍使用类默认参数。
- Walk-Forward 输出了滚动窗口结果，但没有把它作为参数选择的硬约束。

### 3. `ma_cross` 策略本身容易滞后和反复止损

当前 `MaCross` 是 1h 双均线交叉 + 趋势均线过滤 + ATR 初始止损：

- 均线交叉天然滞后，2023 年牛市中仍亏损，说明它没能抓住趋势主段。
- 默认 `fast=45`、`slow=200`，信号慢；但 `trend=100` 又短于慢线，趋势过滤并不稳定。
- ATR 止损只在入场时设置，没有跟踪止损、时间止损、分批止盈或波动状态过滤。
- 胜率长期只有约 17%，策略靠少数大单弥补大量小亏，资金曲线会有很长回撤期。
- `self.buy(sl=sl)` 没有按止损距离计算仓位，实际接近满仓交易，单笔风险不可控。

### 4. `rsi_revert` 过度保守

`RsiRevert` 要求 RSI 超卖且价格在趋势线上方，默认 `oversold=25`、`trend_period=200`。在 `ETH/USDT 1h` 上 3 年多只交易 7 次：

- 信号太稀疏，资金利用率不足。
- 它更像低频补充策略，不适合作为主策略。
- 均值回归策略没有区分震荡和趋势下跌，单靠 RSI 阈值不足以判断反弹质量。

### 5. 缺少市场状态和多周期验证

当前策略主要在 `ETH/USDT 1h` 单资产、单周期上验证。缺失：

- 4h/1d 高周期趋势过滤。
- 波动率状态、成交量状态、趋势强度状态，例如 ADX、ATR 分位数、MA slope。
- 多交易对验证，例如 BTC/USDT、SOL/USDT、BNB/USDT。
- 成本敏感性测试，例如滑点从 0.05% 提高到 0.10%/0.20% 后是否仍有效。

## Phase 1：建立可靠评估框架

目标：先判断策略是否真的有边际优势，再判断参数好不好。

任务：

- [ ] 新增 Buy & Hold 基准和空仓基准，并在报告中强制展示。
- [ ] 新增分段回测：年度、季度、牛市、熊市、震荡市。
- [ ] 新增成本压力测试：
  - commission: 0.05%、0.10%、0.20%
  - slippage: 0.05%、0.10%、0.20%
- [ ] 新增参数稳定性报告，输出热力图数据或表格，不只输出单个最优参数。
- [ ] 将优化目标改为综合评分，而不是单一 `SQN`：
  - `Sharpe` 越高越好
  - `Max Drawdown` 必须低于阈值
  - `# Trades` 必须高于最小样本数
  - `Profit Factor` 必须高于阈值
  - 成本越高惩罚越大
  - 样本外亏损直接淘汰
- [ ] Walk-Forward 输出每个窗口的训练参数、测试结果和参数漂移程度。

建议综合评分：

```text
score = 0.35 * sharpe
      + 0.25 * annual_return
      + 0.20 * profit_factor
      - 0.30 * abs(max_drawdown)
      - 0.10 * turnover_cost
      - penalty_if_trades_too_few
      - penalty_if_oos_negative
```

验收标准：

- [ ] 每个候选策略至少有 30 笔完整交易，或明确标记为低频策略。
- [ ] 样本内、样本外不能只靠一个窗口盈利。
- [ ] 高成本压力测试下仍不能大幅恶化。

## Phase 2：补齐风控和仓位管理

目标：把策略从“信号触发器”升级为“可控风险的交易系统”。

任务：

- [ ] 实现按止损距离计算仓位：

```text
position_size = equity * risk_per_trade / abs(entry_price - stop_loss)
position_size <= equity * max_position_pct / entry_price
```

- [ ] 增加最大持仓比例，避免每次近似满仓。
- [ ] 增加冷却期，连续止损后暂停入场。
- [ ] 增加时间止损，持仓超过指定 bar 且没有盈利则退出。
- [ ] 增加 ATR 跟踪止损，保护趋势单盈利。
- [ ] 增加最大回撤风控：账户回撤超过阈值后降低仓位或停止交易。
- [ ] 将风控逻辑沉淀到策略基类或独立风控模块，避免每个策略重复实现。

验收标准：

- [ ] 单笔最大亏损接近配置的 `risk_per_trade`，不再随 ATR 或价格水平漂移。
- [ ] 最大回撤低于原始策略。
- [ ] 收益不再高度依赖单笔最大盈利交易。

## Phase 3：重构策略方向

目标：不要只在 MA 和 RSI 上调参，应该按市场状态设计策略。

### 3.1 趋势策略 v2

候选逻辑：

- 4h 或 1d 趋势过滤：价格在高周期 EMA/SMA 上方，且均线斜率为正。
- 1h 入场信号：Donchian 突破、EMA pullback、成交量放大突破。
- ADX 或 ATR 分位数过滤：只在趋势强度足够时交易。
- 出场：ATR 跟踪止损 + 时间止损 + 高周期趋势反转。

预期改善：

- 减少均线交叉滞后。
- 降低震荡市反复止损。
- 保留趋势单的右尾收益。

### 3.2 均值回归策略 v2

候选逻辑：

- 只在震荡状态启用，例如 ADX 低、布林带宽度收缩、价格偏离中轨。
- 入场：RSI 低位 + Bollinger 下轨触碰 + 成交量衰减。
- 出场：回到中轨、RSI 回到中性、固定时间止损。
- 禁止在高波动下跌趋势中抄底。

预期改善：

- 提高交易次数。
- 避免 RSI 策略长期空仓。
- 避免趋势下跌中持续接刀。

### 3.3 策略组合

候选组合：

- 趋势策略负责单边行情。
- 均值回归策略负责震荡行情。
- 市场状态分类器决定启用哪类策略。
- 同一时间只允许一个主策略持仓，避免信号互相冲突。

验收标准：

- [ ] 组合策略在年度分段中比单策略更稳定。
- [ ] 回撤持续时间下降。
- [ ] 成本压力测试后仍优于 Buy & Hold 的风险调整收益。

## 建议优先改动清单

第一批改动应按下面顺序执行：

1. 修改 `engine/backtest.py`：新增 `_make_backtest()`，启用 `finalize_trades=True`，接入 `slippage/spread`。
2. 新增 `analysis/data_quality.py`：检查 K线缺失、重复、时区和异常价格。
3. 新增 `analysis/report.py`：生成年度/全区间/交易级别绩效报告。
4. 修改 `run_optimize()`：加入最小交易次数、最大回撤、Profit Factor、样本外结果约束。
5. 修改 `run_walk_forward()`：输出综合评分和参数稳定性，而不是只打印窗口结果。
6. 重写 `MaCross` 为趋势策略 v2：高周期过滤 + 突破/回踩入场 + ATR 跟踪止损。
7. 重写 `RsiRevert` 为震荡策略 v2：先识别震荡状态，再做均值回归。

## 暂时不要做的事

- 不要先上机器学习策略。当前问题主要是回测口径、风控、评估流程和基础策略结构。
- 不要继续扩大网格搜索范围。没有约束的调参只会放大过拟合。
- 不要只看总收益率。当前 `ma_cross` 总收益不差，但胜率、回撤持续时间和年度稳定性都说明它还不适合直接实盘。
- 不要直接用优化结果做实盘信号。优化参数必须经过样本外、成本压力和多资产验证。

## 下一步执行建议

最小可交付版本：

- 第 1 天：修复回测口径，加入 `finalize_trades`、滑点、统一 Backtest 工厂。
- 第 2 天：生成完整报告，复跑当前两个策略，确认真实 baseline。
- 第 3 天：改造优化目标，加入最小交易次数和最大回撤约束。
- 第 4-5 天：实现趋势策略 v2，和当前 `ma_cross` 做同区间对比。
- 第 6-7 天：实现震荡策略 v2，做组合策略初版。

通过这个顺序，系统会先解决“结果是否可信”，再解决“策略是否有效”，最后再解决“参数是否最优”。
