# Alpha Trade - 策略与回测系统优化计划 v2

日期：2026-05-14

## 目标

当前系统已经能完成数据拉取、基础策略回测、参数网格搜索和 Walk-Forward 分析，但策略表现不稳定，且部分回测统计口径会误导判断。本计划的目标不是继续盲目调参，而是先把回测可信度、绩效归因、风控和策略验证流程补齐，再做策略迭代。

优化后的系统应达到以下标准：

- 回测结果可复现，且不会被未平仓交易、缺失滑点、数据缺口或单一指标误导。
- 每个策略都能输出全区间、年度、月度、交易级别、成本敏感性和样本外表现。
- 策略选择以风险调整收益和稳定性为核心，而不是只看单次收益率。
- 实盘信号与回测使用同一套参数、同一套风控和同一套数据完整性检查。

## 为什么回测效果不好

### 1. 回测口径不够严格

`engine/backtest.py` 创建 `Backtest` 时只传了 `cash` 和 `commission`，没有传入 `finalize_trades=True`、`spread/slippage` 和统一的撮合配置。结果是：

- 未平仓交易不会计入交易统计，导致 `# Trades`、胜率、Profit Factor、SQN 等指标失真。
- `config/settings.yaml` 中配置了 `slippage: 0.0005`，但当前回测没有使用它。
- 回测收益包含持仓浮盈浮亏，但交易明细可能不包含最后一笔交易，策略评估会被高估或低估。

### 2. 优化目标过窄

当前 `_grid_search_with_progress()` 只用 `SQN` 选最优参数。这个目标有几个问题：

- 交易次数太少时，`SQN` 本身不稳定。
- 没有约束最大回撤、交易次数、手续费消耗、年化波动、样本外表现。
- 最优参数没有持久化，实盘 `signal` 仍使用类默认参数。
- Walk-Forward 输出了滚动窗口结果，但没有把它作为参数选择的硬约束。

### 3. `ma_cross` 策略本身容易滞后和反复止损

当前 `MaCross` 是 1h 双均线交叉 + 趋势均线过滤 + ATR 初始止损：

- 均线交叉天然滞后，2023 年牛市中仍亏损，说明它没能抓住趋势主段。
- 默认 `fast=45`、`slow=200`，信号慢；但 `trend=100` 又短于慢线，趋势过滤并不稳定。
- ATR 止损只在入场时设置，没有跟踪止损、时间止损、分批止盈或波动状态过滤。
- 胜率长期只有约 17%，策略靠少数大单弥补大量小亏，资金曲线会有很长回撤期。
- `self.buy(sl=sl)` 没有按止损距离计算仓位，实际接近满仓交易，单笔风险不可控。

### 4. `rsi_revert` 过度保守

`RsiRevert` 要求 RSI 超卖且价格在趋势线上方，默认 `oversold=25`、`trend_period=200`。在 `ETH/USDT 1h` 上 3 年多只交易 7 次：

- 信号太稀疏，资金利用率不足。
- 它更像低频补充策略，不适合作为主策略。
- 均值回归策略没有区分震荡和趋势下跌，单靠 RSI 阈值不足以判断反弹质量。

### 5. 缺少市场状态和多周期验证

当前策略主要在 `ETH/USDT 1h` 单资产、单周期上验证。缺失：

- 4h/1d 高周期趋势过滤。
- 波动率状态、成交量状态、趋势强度状态，例如 ADX、ATR 分位数、MA slope。
- 多交易对验证，例如 BTC/USDT、SOL/USDT、BNB/USDT。
- 成本敏感性测试，例如滑点从 0.05% 提高到 0.10%/0.20% 后是否仍有效。
