# Analyze 看盘模块 - 原理讲解

## 一句话原理

`analyze` 做的事可以总结成一句话：

> **从 K 线数据里算出几个公认的技术指标，给每个指标投一票（看多 +1 / 看空 −1 / 中立 0），把票加起来，正得多就是「偏多」、负得多就是「偏空」、不上不下就是「震荡」。AI 只负责把这个结论讲成人话，不参与判断。**

判断结论是**代码用固定规则算出来的**，不是 AI 拍脑袋。所以同样的数据永远得到同样的结论，可复现、可回测。

## 整体流程

```text
数据库K线  →  算指标(snapshot)  →  打分定方向(bias)  →  AI解释(analyst)  →  存成md报告
            indicators/         indicators/         engine/
            snapshot.py         bias.py             analyst.py
```

三个角色，分工很清楚：

| 文件 | 角色 | 比喻 |
| --- | --- | --- |
| `indicators/snapshot.py` | 把 K 线压缩成一组指标数值 | 体检仪器，量出各项数据 |
| `indicators/bias.py` | 按规则给指标打分，得出方向 | 医生，看数据下诊断 |
| `engine/analyst.py` | 调 LLM 把诊断讲成人话 + 存档 | 把诊断翻译给病人听 |

---

## 第一步：算了哪些指标（snapshot）

输入是数据库里取出的 1h K 线（外加 4h K 线看大趋势），输出下面这些数值。每个指标都有它擅长回答的问题：

| 指标 | 通俗解释 | 回答什么问题 |
| --- | --- | --- |
| **MA20 / MA50**（均线） | 最近 20 根、50 根 K 线收盘价的平均 | 现在价格相对「平均成本」是高是低？趋势方向？ |
| **RSI(14)** | 0~100 的强弱指标，衡量最近涨跌力量 | 涨得是不是太猛（超买）？跌得是不是太狠（超卖）？ |
| **MACD(12,26,9)** | 快慢均线之差（DIF）及其平滑线（DEA）、柱状图 | 上涨/下跌的「动能」在增强还是减弱？ |
| **布林带(20,2)** | 均线上下各 2 个标准差画出的通道（上轨/下轨） | 价格在通道里偏高还是偏低？是否触边？ |
| **ATR(14)** | 最近的平均波动幅度 | 现在行情波动有多大（用于估算止损距离）？ |
| **成交量 / 均量(20)** | 当前量 vs 最近 20 根平均量 | 这波动是放量（有人真买卖）还是缩量（没人参与）？ |
| **4h EMA200** | 4 小时级别的 200 周期均线 | **大周期**趋势到底是向上还是向下？ |
| **近期高/低点** | 最近 48 根的最高价、最低价 | 上方压力位、下方支撑位大概在哪？ |

> 关键设计：指标在**全量历史序列**上计算（保证 MA200、EMA200 这种长周期指标准确），然后只取**最后一根**的值作为「当前快照」。

---

## 第二步：怎么打分判断方向（bias）

这是整个模块的核心。一共 **4 个投票指标**，每个投 `+1 / −1 / 0`：

### 4 个投票规则

| 投票项 | 投 +1（看多） | 投 −1（看空） | 否则 0 |
| --- | --- | --- | --- |
| **均线排列** | 价 > MA20 > MA50（多头排列） | 价 < MA20 < MA50（空头排列） | 缠绕，无明确方向 |
| **4h 大趋势** | 4h 收盘 > 4h EMA200 | 4h 收盘 < 4h EMA200 | 4h 数据不足 |
| **MACD** | DIF > DEA 且柱 > 0 | DIF < DEA 且柱 < 0 | 动能不明 |
| **RSI** | 50 ≤ RSI < 70（偏强区间） | 30 < RSI ≤ 50（偏弱区间） | 落在极值区（见风险） |

### 加总定档

把 4 票相加得到总分，再按阈值定方向：

| 总分 | 结论 |
| --- | --- |
| **≥ +2** | **偏多** |
| **≤ −2** | **偏空** |
| **−1 ~ +1** | **震荡** |

逻辑很直白：**要至少两个指标同方向、且没有被反方向抵消，才敢下「偏多/偏空」的结论；否则就是震荡，不轻易表态。**

### 为什么 RSI 极值不投方向票

RSI ≥ 70（超买）或 ≤ 30（超卖）时，RSI 投 **0 票**，不计入方向，而是转成**风险提示**。

因为超买不代表「该买」——恰恰相反，涨太猛往往意味着随时可能回调。把它当方向信号会误导，所以只当风险警示。

---

## 风险提示（不影响方向，只做警示）

除了方向打分，`bias` 还会单独扫出几类风险，列在报告里提醒你：

| 风险 | 触发条件 | 含义 |
| --- | --- | --- |
| RSI 超买 | RSI ≥ 70 | 追高有回调风险 |
| RSI 超卖 | RSI ≤ 30 | 抄底有继续下跌风险 |
| 触布林上轨 | 价格位置 ≥ 100% | 短期偏高 |
| 触布林下轨 | 价格位置 ≤ 0% | 短期偏低 |
| 趋势背离 | 1h 均线方向与 4h 大趋势相反 | 信号可靠性下降 |
| 缩量 | 成交量 < 均量 × 70% | 动能不足，突破/延续不可靠 |

## 完整例子：2026-06-01 的 ETH

用真实报告数据走一遍打分：

| 指标 | 数值 | 投票 | 为什么 |
| --- | --- | --- | --- |
| 均线排列 | 价 2006.73 / MA20 1988.58 / MA50 2005.84 | **0** | 价格在 MA20 上方但 MA20 < MA50，没形成多头排列 |
| 4h 大趋势 | 4h 收盘 2006.73 < EMA200 2148.27 | **−1** | 大周期还在下方 |
| MACD | DIF −0.55 > DEA −4.51，柱 +3.96 | **+1** | 反弹动能在 |
| RSI | 56.1 | **+1** | 落在 50~70 偏强区间 |

**总分 = 0 − 1 + 1 + 1 = +1 → 震荡。**

解读：短线有反弹动能（MACD、RSI 偏强），但大周期趋势仍向下、均线没站稳，所以不构成明确方向，判为震荡。这正是「弱势中的小反弹」。

---

## 为什么要这样设计

1. **结论由代码决定，不是 AI**：方向是 `bias.py` 的固定规则算的。AI 只把它翻译成人话，不能修改方向。同样数据 → 同样结论。
2. **可回测**：因为规则是确定的代码，可以直接接到回测引擎上，验证「偏多时做多」在历史上到底赚不赚钱——这是纯靠 AI 永远做不到的。
3. **可单测**：`tests/test_bias.py`、`tests/test_indicators.py` 测的就是这两层的确定性逻辑。
4. **透明**：报告里每一票怎么投、为什么投，都列出来，你能自己复核，而不是只看一个黑箱结论。

---

## 重要：它不是预测

这套打分判断的是**「当前状态偏多还是偏空」**，是对**现状的描述**，不是对未来价格的预测。

- 它不会、也不应该告诉你「明天会涨到多少」。
- 「偏多」只意味着此刻多个指标共振向上，**不等于**接下来一定涨。
- 最终决策仍然在你手里；AI 那层被严格限制为「只描述、不给买卖建议、不给目标价」。

## 相关文件

| 文件 | 作用 |
| --- | --- |
| `indicators/snapshot.py` | 计算指标快照 |
| `indicators/bias.py` | 打分定方向 + 风险标记 |
| `engine/analyst.py` | 调 LLM 解读 + 生成/保存 md 报告 |
| `main.py` (`analyze` 命令) | 命令行入口 |
| `reports/*.md` | 每次运行自动保存的报告 |

运行方式：

```bash
# 最新数据
.venv/bin/python main.py analyze -p ETH/USDT -t 1h

# 站在某个历史日期
.venv/bin/python main.py analyze -p ETH/USDT -t 1h -d 2026-06-01
```
